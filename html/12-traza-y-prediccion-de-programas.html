12. Traza y predicción de programas

Qué vas a conseguir en esta página

Aprender a seguir un programa de Arduino paso a paso, sin ejecutarlo, para predecir qué aparecerá en el monitor serie y cómo quedarán las salidas, y encontrar los errores antes de cargarlo. Es lo que se evalúa en el examen en papel con el que termina la unidad, y aquí tienes cómo es y cómo prepararlo.

Trazar un programa

Trazar un programa es ejecutarlo tú, con papel y lápiz, como lo haría la placa: línea a línea, apuntando cuánto vale cada variable después de cada paso. Sirve para entender un programa que no es tuyo, para encontrar por qué el tuyo no hace lo que esperabas y para predecir lo que hará antes de cargarlo. Lo has hecho sin darte cuenta cada vez que te has preguntado «¿y ahora cuánto vale brillo?».

Cómo se traza

  1. Apunta las variables con su valor inicial: primero las globales (las de fuera de las funciones) y después las que se crean dentro de setup().
  2. Haz una tabla de traza: una columna por cada variable que cambia, por cada condición que decide algo y por cada salida (lo que se escribe en el monitor serie o cómo queda un LED), y una fila por vuelta del bucle.
  3. Sigue el programa línea a línea. setup() se hace una vez; loop() se repite: rellena una fila por cada vuelta que te pidan.
  4. Al final, escribe exactamente lo que aparece en el monitor serie, línea a línea: print no salta de línea y println sí.

Dónde se suele fallar

  • Una variable global conserva su valor de una vuelta de loop() a la siguiente; una variable creada dentro de loop() vuelve a empezar en cada vuelta.
  • Si todos los números son enteros, la división es entera: 7 / 2 da 3. Y map corta los decimales.
  • Serial.println escribe los números decimales con dos decimales (2.50) si no se le dice otra cosa.
  • Un bucle termina cuando la condición deja de cumplirse: la variable se queda con el valor que hizo falsa la condición, no con el anterior.
  • = guarda un valor y == compara: if (x = 5) se cumple siempre.

Una traza resuelta

¿Qué aparece en el monitor serie en las tres primeras vueltas de loop()?

int cuenta = 0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int veces = 0;
  cuenta = cuenta + 2;
  veces = veces + 1;
  Serial.print(cuenta);
  Serial.print(" ");
  Serial.println(veces);
  delay(500);
}
VueltavecescuentaMonitor serie
10 → 10 → 22 1
20 → 12 → 44 1
30 → 14 → 66 1

cuenta es global y va sumando: 2, 4, 6. veces se crea dentro de loop(), así que en cada vuelta vuelve a valer 0 antes de sumarle 1: siempre escribe 1.

El examen en papel

Cómo es

Se hace sin ordenador y sin apuntes. Con el examen se entrega la hoja de sintaxis de Arduino que tienes aquí debajo: lo que se evalúa no es que recuerdes cómo se escribe cada instrucción, sino que sepas usarlas. Tiene cuatro partes:

C. Trazarellenar la tabla de traza de un programa, vuelta a vuelta, y decir qué escribe al final
D. Escrituraescribir a mano un programa o una función corta que haga lo que se pide

Cómo prepararlo

  • Vuelve a hacer, sin mirar, las prácticas de las páginas 3 a 9.
  • Practica la traza: elige un programa del libro, tapa lo que aparece en el monitor serie, trázalo en papel y compruébalo en Tinkercad o en la placa.
  • Repasa los errores típicos: el ; que falta, una llave sin cerrar, high o serial en minúsculas, = en lugar de ==, la división entera, un for que se queda una vuelta corto y un pin sin pinMode.
  • Haz los ejercicios de la colección de aquí abajo, en papel y sin mirar el resultado hasta terminar cada uno.
  • Relee el apartado «Lo que tienes que saber» del final de cada página.

Ejercicios: predecir, trazar y depurar

Diecisiete ejercicios como los del examen: predecir lo que aparece en el monitor serie, trazar programas vuelta a vuelta, encontrar y corregir errores y escribir programas cortos. Debajo de cada uno tienes el resultado para que compruebes el tuyo. Si un resultado no te cuadra, carga el programa en Tinkercad o en la placa y míralo en el monitor serie.

Simulacro 1 · Predicción: ¿qué aparece en el monitor serie?

No se entrega ni cuenta para la nota: es un ensayo del examen.

void setup() {
  Serial.begin(9600);
  int luz = 650;
  int umbral = 400;
  if (luz < umbral) {
    Serial.println("Farola encendida");
  } else if (luz < umbral + 300) {
    Serial.println("Farola a medias");
  } else {
    Serial.println("Farola apagada");
  }
  Serial.println(map(luz, 0, 1000, 0, 10));
}

void loop() {}
Ver la solución

650 < 400 es falso. En el else if, umbral + 300 vale 700 y 650 < 700 es verdadero: escribe Farola a medias. Después, map(650, 0, 1000, 0, 10) daría 6,5, pero map corta los decimales: escribe 6.

Simulacro 2 · Errores: encuentra y corrige

No se entrega ni cuenta para la nota: es un ensayo del examen.

Este programa debería hacer parpadear el LED azul, medio segundo encendido y medio segundo apagado. Tiene un error de sintaxis y otro de lógica.

Ver la solución
  • Línea 8: high en minúsculas no existe; es HIGH (sintaxis: no compila).
  • Línea 10: vuelve a escribir HIGH, así que el LED no se apaga nunca; tiene que ser LOW (lógica: compila, pero el LED se queda encendido).

Simulacro 4 · Escritura

No se entrega ni cuenta para la nota: es un ensayo del examen.

Escribe un programa que, cada segundo, lea la temperatura del LM35, la escriba en el monitor serie con un decimal y encienda el LED rojo si pasa de 28 °C (y lo apague si no). Usa constantes para los pines y para el límite.

Ver una solución
const int LM35 = A2;
const int LED_ROJO = 12;
const float LIMITE = 28.0;

void setup() {
  pinMode(LED_ROJO, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  float temp = analogRead(LM35) * 5000.0 / 1023 / 10;
  if (temp > LIMITE) {
    digitalWrite(LED_ROJO, HIGH);
  } else {
    digitalWrite(LED_ROJO, LOW);
  }
  Serial.println(temp, 1);
  delay(1000);
}

Con el LM35, cada grado son 10 mV: la lectura se pasa a milivoltios con * 5000.0 / 1023 y a grados dividiendo entre 10. El 5000.0 con decimal evita la división entera.

Lo que tienes que saber de esta página

  • Trazar es ejecutar un programa en papel, línea a línea, apuntando el valor de cada variable en una tabla.
  • setup() se hace una vez y loop() se repite; las variables globales conservan su valor entre vueltas y las de dentro de loop() vuelven a empezar.
  • Errores de sintaxis: el programa no compila (falta ;, una llave, mayúsculas). Errores de lógica: compila, pero hace otra cosa.
  • Cuidado con la división entera, los decimales que corta map, print frente a println y = frente a ==.
